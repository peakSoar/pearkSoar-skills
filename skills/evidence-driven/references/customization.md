# 仓库定制

仅在初始化或转换 Harness 时读取。

## 填写模板前先核验

从仓库和用户指令确认以下事实：

- 支持的产品、平台、运行时和明确非目标；
- 模块边界，以及每项规则、状态、生命周期和序列化行为的实际 owner；
- 持久化与数据保留边界；
- 生成式契约源和漂移检查；
- 独占资源、并发规则和清理行为；
- 敏感数据及其禁止出现的位置；
- 定向、回归、静态、契约、UI、构建和发布命令；
- 需要授权的破坏性、外部、真实数据、依赖、凭据和发布操作；
- 既有 Git 约定和脏工作区规则。

使用源码和测试标记事实等级。若仓库只表达了目标架构，应记录为目标或证据缺口，而不是 `CONFIRMED`。

## 选择模板资产

`assets/harness-template/` 提供完整基线，只复制目标仓库真正需要的文件：

- `AGENTS.md`：恢复入口、边界、owner、证据、权限和工作区规则；
- `docs/改造计划与进度.md`：跨会话阶段任务的唯一状态；
- `docs/当前阶段与下一步.md`：跨会话继续点；
- `docs/阶段/S00-阶段模板.md`：真实阶段合同；
- `docs/验证规则.md`：通用验证和反馈路由；
- `docs/验收/当前验收.md`：最近证据快照。

已有等价文件时，将职责合并到既有位置。不得为了匹配模板文件名建立第二权威。

## 完整结构的确定性生成

只有用户明确要求完整结构时才运行脚本。先执行只读预检：

```text
python scripts/scaffold_harness.py --target <目标仓库> --project-name <项目名称> --dry-run
```

确认目标与文件计划正确后，使用同一命令去掉 `--dry-run`。脚本按固定 manifest 生成 `AGENTS.md` 和五份 `docs/` 文件，并检查模板资产没有缺失或意外新增。

默认情况下，任一目标文件已存在都会使脚本在写入前退出。检查现有文件且明确决定保留后，可以增加 `--keep-existing`，让脚本跳过已有文件并只创建缺失项。脚本不提供覆盖模式。

脚本只负责确定性生成结构和替换 `{{PROJECT_NAME}}`，其余占位符仍须依据仓库事实填写。不得把脚本成功等同于 Harness 已完成定制或验收。

## 填写与精简

搜索所有 `{{...}}`，使用已确认的项目事实替换；无法确认时记录为明确证据缺口。删除没有实际决策价值的章节，只在确实改变智能体行为时加入项目专项规则。

不要把实现历史、过期测试数字、单次事故或推测性未来功能写入长期指令。重复操作细节应集中在验证规则或阶段合同中。

## 转换检查

交付前确认：

- 当前阶段状态只有一个权威；
- 状态表、机器可读状态、接力和验收不存在冲突；
- 只存在一个活动阶段或 active reopen；
- 所有链接和引用文件存在；
- 除明确记录的证据缺口外，不残留未处理占位符；
- 当前验收不包含历史结果或敏感内容；
- owner 事实和验证命令符合当前 checkout；
- 用户预存修改未被触及；
- 最终结构不超过项目真实协作需要。
