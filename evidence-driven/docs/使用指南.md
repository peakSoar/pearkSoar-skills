# 使用指南

## 安装

本仓库将实际 Skill 放在 `skills/evidence-driven/`。根据使用范围复制整个目录：

- 个人跨项目使用：复制到 `~/.agents/skills/evidence-driven/`；
- 团队仓库使用：复制到目标仓库的 `.agents/skills/evidence-driven/` 并纳入版本控制。

Skill 文件夹必须保持完整，至少包含 `SKILL.md`；`references/` 和 `assets/` 支持按需加载和模板生成。

## 调用模式

### 初始化或转换

适用于新建 Harness，或将零散规范、计划和验收文档转换为单一工作流。

```text
使用 $evidence-driven 为当前仓库建立 AI 工程 Harness。
```

Skill 会先读取仓库事实，再从模板中选择必要文件。它不会把模板中的目标架构冒充为当前事实。

当用户明确要求构建完整结构时，Skill 必须使用脚本而不是依靠提示词手工创建：

```text
python skills/evidence-driven/scripts/scaffold_harness.py --target <目标仓库> --project-name <项目名称> --dry-run
python skills/evidence-driven/scripts/scaffold_harness.py --target <目标仓库> --project-name <项目名称>
```

脚本要求 Python 3.10 或更高版本，只使用标准库。

脚本默认不覆盖已有文件。确认保留已有 Harness 文件并补齐缺失项时，使用 `--keep-existing`。脚本生成结构后，仍需根据仓库事实填写其他模板占位符并执行验证。

### 执行

适用于明确要求按 Harness 完成开发任务。

```text
使用 $evidence-driven 按现有 Harness 完成这个修改并验证。
```

Skill 会恢复当前状态、保护预存修改、追踪 owner，并根据任务风险选择验证范围。

### 审计

适用于检查 Harness 是否存在状态漂移、重复 owner、旧验收或权限问题。

```text
使用 $evidence-driven 审计这个仓库的 Harness，只报告问题，不修改文件。
```

## 定制模板

模板位于 `skills/evidence-driven/assets/harness-template/`。所有 `{{...}}` 都是待替换字段，必须由目标仓库事实填写；无法确认时应记录证据缺口，而不是猜测。

普通局部任务不需要创建阶段。只有跨会话、跨模块、高风险、发布或需要人工操作的工作才应启用完整阶段状态机。

## 更新

更新 Skill 时保持 `name: evidence-driven` 稳定，优先缩小和澄清触发描述。项目专属事实应留在目标仓库，不应回写到通用 Skill。
