# 工作流模型

初始化、转换或审计 Harness 时读取。已有 Harness 下的普通任务应遵循仓库自身规则，不必重复加载本文。

## 权威分层

| 层级 | 唯一职责 | 不得拥有 |
| --- | --- | --- |
| 仓库指令 | 长期产品、架构、owner、安全、权限和工作区边界 | 当前测试结果 |
| 计划与进度 | 唯一当前阶段、状态、依赖、重开状态和导航 | 详细实施证据 |
| 当前接力 | 最近继续点和下一会话提示 | 独立阶段状态 |
| 阶段合同 | 单阶段证据、范围、fixture、实施、验证和退出条件 | 全局状态权威 |
| 验证规则 | 通用检查层次、状态边界、反馈路由和人工操作矩阵 | 历史结果 |
| 当前验收 | 最近命令、结果、未运行项和剩余风险 | 阶段权威或累积历史 |
| 源码、测试和运行数据 | 生产事实 | 项目计划策略 |

## 恢复顺序

```text
仓库指令
-> 计划与唯一状态
-> 当前接力
-> 当前阶段合同
-> 仅阅读阶段引用的源码、测试和验证规则
-> 需要最近执行证据时读取当前验收
-> 核对 HEAD、分支、状态和预存修改
```

聊天摘要只能辅助定位证据，不能覆盖仓库状态或源码事实。

## 任务分类

普通任务适用于局部、低风险、预计单会话完成且不需要发布或人工操作的工作。它仍需保护范围并进行与风险相称的验证，但不创建或修改阶段状态。

阶段任务适用于跨会话、跨模块、改变重要边界、风险较高、参与发布或需要人工授权与真实操作的工作。同一时刻只允许一个活动阶段或 active reopen。

## 证据等级

| 等级 | 含义 | 使用边界 |
| --- | --- | --- |
| `CONFIRMED` | 多类证据交叉一致 | 可驱动设计和实现 |
| `CODE_CONFIRMED` | 当前源码或测试直接确认 | 可驱动生产实现 |
| `DATA_CONFIRMED` | 当前运行、数据库、日志或产物直接确认 | 可驱动诊断和验收 |
| `STRONG_INFERENCE` | 多项证据支持但缺一个直接闭环 | 只能驱动可逆验证 |
| `HYPOTHESIS` | 尚未核验 | 只能驱动调查 |

改变生产行为前，必须找到 producer、所有相关 transition、真正作出决策的 consumer 和唯一 owner，并判断现有测试是在保护目标不变量还是固化旧错误。

## 实施反馈链

```text
冻结基线
-> characterization fixture
-> 目标红灯
-> 最小实现
-> 定向绿灯
-> 受影响回归
-> 静态与契约门禁
-> 必要真实产品验收
-> 覆盖当前验收
-> 退出或反馈回流
```

纯文档、注释或不改变行为的机械修改可以不制造红灯，但必须在验收中说明原因。

## 状态机

```text
NOT_STARTED -> IN_PROGRESS -> DONE
IN_PROGRESS -> HUMAN_ACTION_REQUIRED -> IN_PROGRESS
IN_PROGRESS <-> BLOCKED
DONE -> REOPENED -> IN_PROGRESS -> DONE
```

- 实现或回归失败留在 `IN_PROGRESS`。
- 已复现的环境或权限失败进入 `BLOCKED`。
- 自动工作完成、等待用户授权或真实操作时进入 `HUMAN_ACTION_REQUIRED`。
- 新证据推翻已完成 owner 时，重开最早责任阶段。
- 只有退出条件满足且当前验收通过，才能进入 `DONE`。

不得通过削弱断言、改变 fixture 含义、手工修补数据、跳过失败或增加无期限兼容路径制造成功。

## 验收与接力

《当前验收》只记录最近一轮证据：目标 HEAD 与工作区、范围、预存修改、实际修改、命令和结果、状态变化、未运行项及剩余风险。它不得包含项目定义的密钥或敏感载荷。

当前接力记录下一会话的继续点和约束。它可以投影阶段状态用于定位，但不得成为竞争状态权威。
